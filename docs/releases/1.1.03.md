# DankTech2 1.1.03

## Pack preservation fixes

- Trash Pack upgrades now read the existing `trash_instance` metadata. Previously, the Dank Crafter looked under the Dank Pack key and replaced a configured Trash Pack with a new empty instance. Upgrades now retain the original long ID, all 18 filter entries, their exact stored item payloads, and unknown nested metadata while changing only the tier. An unreadable existing instance is refused before ingredients are consumed.
- Building with an empty or cleared selected Dank Pack slot now displays `Selected slot is empty.` instead of throwing an exception. The retained final item and existing custom-block restrictions remain in place.
- Admin cloning now delivers and registers the replacement before invalidating the original. Full inventories and partial delivery restore the previous inventory, and a failed registry save keeps the original valid. Replacement IDs skip occupied values and the original ID; stale menu entries cannot clone an already-replaced pack again.
- Replaced Dank Packs cannot re-register their old ID through an already-open pack menu, an older admin menu, or the Dank Crafter. Existing valid packs retain their normal controls, and new pack crafting remains available. Valid Dank Pack upgrades also retain unknown nested metadata while changing only the tier.
- Registry writes copy crafted and recovered pack templates to Bukkit's serializable `ItemStack` representation without changing their item metadata or persistent payload. Template subclasses previously wrote a Slimefun-specific YAML alias that could deserialize to a missing item after restart. Loading now recognizes that known historical alias and refuses any remaining unreadable item entry before handlers start, keeping the original registry file available for repair.

Alias recovery requires the original serialized item payload to remain in the registry. A record that has already lost that payload still needs recovery from an existing pack or a backup. Owner-only records remain readable and keep their existing identity.

## Existing safeguards retained

Strict registry loading and staged YAML writes were already present in the current 1.1.02 download and maintained addon bundle. This release retains them. It does not rename item IDs or persistent keys, change recipes, change pack capacities, or alter pickup and Cargo rates.

## Compatibility and distribution

- Minecraft 1.21.11 and Java 21 remain the minimum.
- Paper 26.3 is the primary current compatibility target; the distributable is compiled against the 1.21.11 API floor.
- Download the raw `SF_DankTech21.1.03.jar` and replace the previous DankTech2 JAR.
- Version 1.1.03 uses a new source tag; the previous 1.1.02 release is not replaced.

Automated inventory and metadata fixtures cover the changed paths. They are not a guarantee for every historical world, external plugin callback, storage failure, or Folia region interaction.
