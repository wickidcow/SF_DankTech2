# DankTech2 1.1.04 — WildStacker 2026.3 API alignment

**Unreleased validation candidate.** The existing published 1.1.03 JAR and all previous artifacts remain unchanged.

## Source updates

- Replace the optional, provided-only `com.bgsoftware:WildStackerAPI:2023.2` compile dependency with pinned **2026.3**.
- Preserve BG-Software's documented Java API and the existing `getItemAmount(Item)` / `getStackedItem(Item).setStackAmount(amount, true)` operations without writing a second stack implementation, reflection bridge, or local imitation API.
- Do not embed WildStacker classes in DankTech2. The installed WildStacker plugin remains the optional runtime provider.
- Retain RoseStacker and mcMMO integration, Dank Pack/Trash Pack saved YAML/PDC data, IDs, recipes, stack capacities, pickup accounting, anti-dupe protections and machine tick behavior.
- Require the correct version and direct API calls in the CI source-invariant check. Keep a distinct 1.1.04 raw JAR filename and source tag.

## Release gates

The API release listing and upstream method signatures are evidence of an available version, **not** proof that the Maven repository reliably serves the POM and JAR. The previous BG-Software Maven endpoint returned HTTP 504. This candidate must prove exact source dependency resolution, Maven unit tests, Java 21 bytecode, and Paper 1.21.11 / 26.2 / 26.3 compilation in GitHub Actions. A failed external download is a blocker, not a reason to claim compatibility or skip tests.

Before production use, verify installed WildStacker 2026.3 item stacks and the standalone DankTech2 1.1.04 candidate on a backed-up Paper/Purpur test server. Exercise normal/stacked pickups, full packs, conservation of item counts, Trash Pack void rules, RoseStacker alternative paths and repeated restarts. Do not republish the immutable 1.1.03 artifact.

Slimefun Legacy 4.1.78's maintained addon source manifest should pin **only the final validated and published source SHA** after this addon is released. Existing optional asset bytes, Bedrock/Geyser functionality, server/world data and 45-addon release gates are untouched by this PR.
